# Modbus RTU 调试

## 在开始之前核对

当前 UART1 为 TX GPIO5、RX GPIO6；本次从站测试数据位 8、停止位 1。波特率和校验方式必须对照从站手册及设备实际设置。绿色 A/B 接线正确、参考地按手册、从站单独供电。没有从站时查询超时不能证明模块损坏。

## 正确的只读示例

示例条件：从站地址 1，功能码 03，起始保持寄存器协议地址 0x0000，数量 2。

```text
报文体：01 03 00 00 00 02
CRC：   C4 0B
完整：  01 03 00 00 00 02 C4 0B
```

选择 HEX，输入报文体并启用 CRC-16/MODBUS；或者输入完整帧并关闭 CRC 追加。不要对完整帧重复追加 CRC。串口校验位（N/E/O）与报文 CRC 是两种不同机制，不能互相替代。

以下演示应答表示两个原始寄存器 0x007B 与 0x002D：

```text
01 03 04 00 7B 00 2D 4A 37
```

4A 37 为正确的低字节优先 CRC。界面演示由报文体即时计算该值，并通过回归测试验证。数值的物理意义、倍率、单位、正负数、浮点和字序都需按目标设备手册解释，不能仅凭十六进制推断。

## 常见误判

| 现象 | 先检查 |
|---|---|
| 只有 TX，没有 RX | CRC、从站电源、参数、地址、A/B 与寄存器是否支持 |
| 收到与发送完全相同的数据 | 可能为回显或回环，尚不能作为有效从站应答 |
| 文本栏出现替换符 | 二进制转 UTF-8 的显示结果，优先看 HEX |
| RX 分成多行或合在一行 | 当前按 UART 数据块记录，不是 Modbus 帧边界 |
| 周期发送偶尔失败 | 周期可能未覆盖从站处理和应答时间；先单次验证 |
| “UART 已发完”却没有读数 | 仅说明 MCU 发完字节，尚未确认从站执行 |

## 当前协议边界

没有自动地址扫描、自动波特率识别、寄存器映射、RX CRC 标记、RTU 分帧、异常码解释、请求应答配对或事务重试。定时发送是原始报文调度，不是等待应答后再发下一条的主站状态机。发送间隔也不等于 Modbus 帧间隔或应答超时。

默认示例用于读寄存器，不能代表所有从站都支持地址 0x0000。实际寄存器手册中的 40001 等显示编号与协议中的偏移可能不同，应按手册换算。
