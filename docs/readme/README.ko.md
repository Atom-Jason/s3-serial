# S3 Serial

### ESP32-S3를 휴대용 Wi-Fi 시리얼 및 RS485 디버거로 만드세요.

<img src="../assets/banner.svg" alt="S3 Serial" width="100%" />

PC와 휴대폰에서 사용하는 오프라인 웹 작업 공간입니다. UART 설정, HEX／UTF-8 송수신, Modbus CRC 추가, 반복 전송 및 로그 내보내기를 지원합니다. 화면과 번역은 펌웨어에 포함되며 클라우드나 외부 CDN이 필요하지 않습니다.

## 언어

첫 화면은 브라우저 언어와 관계없이 **English**로 표시됩니다. 오른쪽 위에서 English, 简体中文, 繁體中文, 日本語, 한국어를 선택하면 브라우저가 선택을 기억합니다. 언어 변경은 재연결, UART 설정 적용, 데이터 전송 또는 입력 삭제를 하지 않습니다. 이전 로그, 사용자가 지정한 명령 이름, 원시 데이터 및 장치 진단 문자열은 그대로 유지됩니다. 상세 기술 문서는 현재 중국어 간체로 제공됩니다.

명시적 브라우저 데모의 실제 화면 캡처입니다. 휴대폰 이미지는 뷰포트 시뮬레이션이며 실제 휴대폰 테스트나 RS485 통신 성공의 증거가 아닙니다.

## 배선

| ESP32-S3 | EKT010 | 현재 하네스 색상 |
|---|---|---|
| 3V3 | VCC | 빨강 |
| GND | GND | **파랑** |
| GPIO5 / UART1 TX | RXD, 모듈 입력 | **검정** |
| GPIO6 / UART1 RX | TXD, 모듈 출력 | 노랑 |

**접지는 파란색이며 검은색은 RXD입니다.** A+와 B−를 슬레이브의 해당 신호에 연결하세요. 기준 접지와 별도 전원은 슬레이브 설명서를 따르세요. B−는 전원 음극이 아닙니다. 외부 DE/RE 핀이나 방향 제어 GPIO는 없습니다. 다른 케이블은 표기와 도통을 확인하세요. [배선도](../HARDWARE.md).

## 빠른 시작

ESP-IDF v5.5.1을 설치하고 환경을 활성화한 뒤 프로젝트 루트에서 실행하세요.

```sh
idf.py set-target esp32s3
idf.py build
idf.py -p YOUR_PORT flash monitor
```

YOUR_PORT를 실제 포트로 바꾸세요. 4 MB Flash 주소 공간을 사용하며 PSRAM은 필요하지 않습니다. USB 부팅 로그에서 무작위로 생성된 비밀번호를 확인하고 S3-Serial-xxxx에 연결한 다음 **http://192.168.4.1** 을 여세요. Wi-Fi와 웹 로그인은 같은 비밀번호를 사용하며 공통 고정 비밀번호는 없습니다.

제어권을 얻고 슬레이브 설명서에 맞는 보레이트와 패리티를 확인한 뒤 설정을 적용하세요. 확인 후 장치에 저장하면 재시작 후에도 유지됩니다. 저장된 설정이 없을 때 초기값인 115200/8N1은 슬레이브 설정을 의미하지 않습니다.

## Modbus 예제

주소 1의 슬레이브가 프로토콜 주소 0x0000부터 홀딩 레지스터 두 개 읽기를 지원하는 경우의 예제입니다.

```text
입력: 01 03 00 00 00 02
CRC 추가 후: 01 03 00 00 00 02 C4 0B
응답 예: 01 03 04 00 7B 00 2D 4A 37
```

완전한 8바이트를 입력한 경우 CRC 추가를 끄세요. 시리얼 패리티와 프레임 CRC는 별도의 검사입니다. UART 전송 완료는 슬레이브의 수신 또는 실행 완료를 보장하지 않습니다. [Modbus 안내](../MODBUS.md).

## 하드웨어 없이 체험

```sh
python tools/preview.py
```

http://127.0.0.1:8765/?demo=1 을 여세요. 데모는 실제 장치에 접근하지 않습니다. 실제 장치에서는 demo=1이 없는 루트 경로를 사용하세요.

## 기능 및 제한

- 1200~115200, 사용자 지정 보레이트, 5~8 데이터 비트, N/E/O, 1/2 정지 비트, HEX／UTF-8, CRC, 명령 32개, TXT/CSV 내보내기.
- 최대 3개 디버거 페이지와 1개 제어권 소유자를 지원합니다. 15초 동안 하트비트가 없으면 제어권이 해제됩니다. 휴대폰 백그라운드 상태에서 반복 전송이 중지될 수 있습니다.
- 반복 간격은 20 ms~1 h입니다. 슬레이브 응답을 기다리지 않으므로 처리 및 응답 시간을 고려하세요. 재연결 시 자동 재전송 또는 작업 재개는 하지 않습니다.
- RX는 읽기 블록입니다. RTU 자동 프레임 구분, 수신 CRC 검증, 요청/응답 연결 및 응답 시간 초과 처리는 구현되지 않았습니다.
- 기록은 브라우저에서 원시 데이터 5 MiB／20000개, 장치에서 32 KiB／512개로 제한됩니다. 제거된 기록은 내보낼 수 없고 전원이 꺼지면 RAM 기록이 사라집니다.
- BLE, OTA 및 영구 오프라인 수집은 구현되지 않았습니다. 로컬 AP 또는 신뢰할 수 있는 LAN에서 사용하세요.

프런트엔드 17개 테스트, C11 코어, 빌드 및 파일 검증을 통과했습니다. 이 공개 빌드는 아직 실제 보드에 기록하지 않았습니다. 실제 RS485 왕복 통신과 장시간 검증은 남아 있습니다. [검증 범위](../VERIFICATION.md).
